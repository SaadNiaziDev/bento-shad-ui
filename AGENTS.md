# AGENTS.md

Instructions for AI agents and contributors working **on this repository**. To *use* the library in another project, read `llms-full.txt` instead.

## Layout

| Path | What | Edit? |
|---|---|---|
| `src/tokens.json` | Every colour (hex, light + dark), font, size, shadow | yes |
| `src/css/components.css` | All component CSS; reads tokens only | yes |
| `src/core/*.ts` | Vanilla behaviours (theme, toast, popover, widgets, delegated events) | yes |
| `src/react/*.tsx` | React components | yes |
| `src/illustrations/*.ts` | Pencil characters: `kit.ts` (sketch primitives, face and moods), `characters.ts` (the cast), `index.ts` (public API), `browser.ts` (script-tag auto-render) | yes |
| `registry/bento-grid.tsx` | shadcn registry component source (not type-checked here: it imports `@/lib/utils`) | yes |
| `docs/*.md` | Guides; concatenated into `llms-full.txt` and rendered on the website | yes |
| `docs/components/*.md` | One page per component (see "Component pages" below) | yes |
| `site/home.html`, `site/sprite.svg`, `site/assets/*` | Website landing page, icon sprite, docs CSS/JS | yes |
| `scripts/docs.mjs` | Builds the website into `_site/` (not committed; Pages builds it) | yes |
| `scripts/build.mjs`, `scripts/color.mjs` | Build | yes |
| `test/*.test.mjs` | Node test runner tests against `dist/` | yes |
| `dist/`, `r/`, `llms-full.txt` | Generated by `npm run build` | **never by hand** |

## Commands

```bash
npm install
npm run typecheck   # tsc --noEmit, strict
npm run build       # dist/, r/, llms-full.txt
npm test            # node --test test/
npm run docs        # website → _site/ (fails on broken links or unknown props tables)
npm run docs:serve  # http://localhost:4321/bento-shad-ui/
npm run check       # typecheck, build, test, docs
```

CI runs `npm run check` and fails if `dist/` differs from a fresh build, so always build and commit `dist/` with source changes.

## Rules

- **Tokens only.** Component CSS must not contain colour literals except `#fff` inside a white thumb or knob and `rgb(0 0 0 / x)` in shadows and backdrops. New colours go into `src/tokens.json` in both themes.
- **Contrast.** New text/background token pairs go in `test/tokens.test.mjs` (4.5:1 for text, 3:1 for `input`/`ring`).
- **No monospace font.** Don't add `--font-mono` or monospace stacks anywhere (a test enforces this).
- **Class prefix `bk-`; variants via `data-*`.** Never add `!important` to component rules.
- **Core must be SSR-safe.** No `window` or `document` at module top level; guard with `isBrowser`.
- **React components** forward refs, spread remaining props onto the root, support controlled and uncontrolled state, and put `data-bk-react` on stateful roots so the vanilla core skips them.
- **Public API = class names, data attributes, token names, exported functions and React props.** Changing or removing any of them is a breaking change: note it in `CHANGELOG.md`.
- **Characters.** Draw in painting order with the `Sketch` kit; colours only from the palette (tint tokens). Lines stay `currentColor`. A new character needs at least three distinctive traits, suggested uses, and must read clearly in all six moods and in dark mode. Keep characters original: no likeness of existing mascots or brands.
- **Docs.** A new component needs a page in `docs/components/` and a link in `docs/components.md`; update the component list in its group tile on `site/home.html` and the count in `llms.txt`. Tests check that every `bk-` class used in the docs and the site exists in the CSS.

## Component pages

Each `docs/components/<name>.md` starts with frontmatter:

```
---
title: Button
description: One sentence, shown under the title and in search.
group: Actions   # Layout | Actions | Forms | Data display | Feedback | Overlays | Navigation
---
```

- ` ```html preview ` renders the HTML live with Preview / HTML tabs (`preview full` stretches it to full width). Icons come from the site sprite (`<use href="#i-plus"/>`).
- `<!-- props: ButtonProps -->` inserts a props table generated from the TypeScript types and JSDoc. Every exported `*Props` member needs a JSDoc comment.
- Sections in order: Usage (React, then HTML), Examples, API, Accessibility.

## Releasing

Published to npm as `bento-shad-ui`. Versions on npm are permanent: a published version can never be changed or reused.

1. Update `version` in `package.json` and add a `CHANGELOG.md` entry. Update pinned versions in the docs (`cdn.jsdelivr.net/npm/bento-shad-ui@X.Y.Z`, registry `/vX.Y.Z/` URLs) and the README.
2. `npm run check`, commit, then `git tag vX.Y.Z && git push --follow-tags`.
3. `gh release create vX.Y.Z --notes-file <notes>`. `.github/workflows/publish.yml` publishes to npm through trusted publishing (no token, with provenance) and skips a version that is already on npm. GitHub Pages redeploys from `main`.
4. Check `npm view bento-shad-ui version` and the jsDelivr URL.
